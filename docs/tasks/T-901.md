# T-901 — Monthly seller invoice for Manual orders above the free quota

## Goal
After Gate D, on the 1st of each month every non-exempt seller with more than 50 confirmed Manual orders last month gets an invoice for Rp1.000 per order above 50, by WhatsApp and on the dashboard.

## Context
- ADR 0006 (decision and open interpretations), T-407 (usage data).
- ADR 0002 is unaffected: the invoice is DropKilat's own fee, paid by the seller. No buyer money is involved.
- **Blocked until:** Gate D passed **and** Nur has done the tax/legal check (invoice format; PPN if DropKilat is PKP).

## Scope
- In:
  - migration with `invoices` and `invoice_lines`;
  - `invoicer` worker;
  - invoice page and printable view for the seller;
  - `wa.seller_invoice`;
  - owner screen to mark an invoice paid (manual bank transfer to DropKilat);
  - reminders.
- Out: automatic collection, card payments, blocking sellers for unpaid invoices (not decided).

## Interfaces
```sql
CREATE TABLE invoices (
  id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  seller_id   uuid NOT NULL REFERENCES sellers(id),
  number      text NOT NULL UNIQUE,             -- DK-INV-YYYYMM-<seq>
  month       date NOT NULL,
  amount      bigint NOT NULL CHECK (amount >= 0),
  status      text NOT NULL CHECK (status IN ('issued', 'paid', 'void')),
  issued_at   timestamptz NOT NULL, paid_at timestamptz,
  UNIQUE (seller_id, month));
CREATE TABLE invoice_lines (
  invoice_id  uuid NOT NULL REFERENCES invoices(id),
  seller_id   uuid NOT NULL REFERENCES sellers(id),
  description text NOT NULL, qty integer NOT NULL, unit_price bigint NOT NULL,
  amount      bigint NOT NULL CHECK (amount = qty * unit_price));
-- tenant RLS on both; audit_log on issue, paid, void
```

## Acceptance criteria
1. Running the invoicer twice for the same month creates one invoice per seller (`UNIQUE (seller_id, month)`).
2. Invoice amount = (confirmed − 50) × Rp1.000 for non-exempt sellers. A seller at or below 50 gets no invoice. Exempt sellers get none.
3. Refund rule per the answer below. The test covers an order refunded in the same month and one refunded in a later month.
4. Reminders at +7 and +14 days if unpaid; nothing is blocked.
5. All amounts `int64` rupiah; invoice and lines reconcile in a SQL test.

## Test expectations
- Integration with the fake clock across a month boundary; idempotency of the worker; RLS.

## Risks and notes
- Real money and tax: escalate any change in amounts or rules to Nur.

## Questions
- (TL → Nur) Does an order refunded later still count as confirmed? Default in ADR 0006: counted if refunded in a later month, not counted if refunded in the same month before the invoice.
- (TL → Nur) Unpaid invoices: default is reminders only, no blocking. Confirm before Gate D.
- (TL → Nur) Bank account and legal entity name printed on the invoice.
