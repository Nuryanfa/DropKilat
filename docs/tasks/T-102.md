# T-102 — platform/db with RLS context helpers and migration 000002

## Goal
Every transaction in the app runs in exactly one RLS context (`system`, seller, `buyer`, `public`). The `public` hole in migration 000001 is closed.

## Context
- **ADR 0004** (decision, exact SQL and the expected result table).
- `docs/database-schema.md` §4 and §9 (migration rules).
- `deploy/init-db.sql` (the `dropkilat_app` role).

## Scope
- In:
  - `internal/platform/db`: pool, the four transaction helpers, migrate command;
  - `migrations/000002_rls_contexts.up.sql` / `.down.sql`, copied from ADR 0004;
  - a testcontainers fixture that creates the app role exactly as `deploy/init-db.sql` does;
  - `/readyz`.
- Out: sqlc queries for domain tables (each domain card), CI wiring (T-104).

## Interfaces
```go
package db

func NewPool(ctx context.Context, url string) (*pgxpool.Pool, error)

func WithSystemTx(ctx context.Context, p *pgxpool.Pool, fn func(pgx.Tx) error) error
func WithSellerTx(ctx context.Context, p *pgxpool.Pool, sellerID uuid.UUID, fn func(pgx.Tx) error) error
func WithBuyerTx(ctx context.Context, p *pgxpool.Pool, buyerID uuid.UUID, fn func(pgx.Tx) error) error
func WithPublicTx(ctx context.Context, p *pgxpool.Pool, fn func(pgx.Tx) error) error // read-only tx

// Migrate runs golang-migrate with DK_MIGRATE_DATABASE_URL (owner role).
func Migrate(ctx context.Context, url string, direction string) error
```
- Set the context with `SELECT set_config('app.role', $1, true)` (and `app.seller_id` / `app.buyer_id`). `SET LOCAL` cannot take bind parameters; never build the statement with string formatting.
- `WithPublicTx` begins with `pgx.TxOptions{AccessMode: pgx.ReadOnly}`.
- On error or panic the transaction is rolled back; the panic is re-raised.
- CLI: `dropkilat migrate up|down|version`. The Makefile `migrate` target may keep using the `migrate` binary.
- `/readyz`: 200 when the pool pings and the schema version equals the highest migration in the binary (embed `migrations/` with `embed.FS`); otherwise 503.

## Acceptance criteria
1. Migration 000002 matches ADR 0004 exactly; `make migrate-check` (up → down → up) passes.
2. Integration tests through the helpers, connected as `dropkilat_app`, reproduce every row of the ADR 0004 result table:
   - `public`: 1 drop, 1 variant, 0 orders; variant update affects 0 rows; order insert → RLS error.
   - `buyer`: own order only, can update it, cannot change `buyer_id`, cannot update variants.
   - `public` with `app.buyer_id` set → 0 orders.
   - Seller B: 0 of seller A's orders. Seller A and `system`: all.
   - No context: 0 rows.
3. A write inside `WithPublicTx` fails (read-only transaction).
4. The context does not leak: after a `WithSellerTx` on a pooled connection, a plain query on the same connection sees 0 tenant rows. Run it with a pool of size 1.
5. As `dropkilat_app`, `UPDATE`/`DELETE` on `audit_log` fails with permission denied.

## Test expectations
- Integration: testcontainers PostgreSQL 17, real migrations, fixture creating `dropkilat_app`.
- Unit: rollback on error and on panic.

## Risks and notes
- This is the tenant-isolation foundation; Gemini will attack it in T-306. Keep the helpers tiny.
- Do not edit migration 000001 (merged).
- `/readyz` reads `schema_migrations` as the app role. The default privileges in `deploy/init-db.sql` already grant it `SELECT`; add a test for that. Do not widen grants in 000002.
