# T-407 — Free-quota usage meter for Manual orders

## Goal
Each seller sees how many confirmed Manual orders they have this month against the free quota of 50. The data is exact enough to invoice from after Gate D (T-901). During the pilot nothing is charged and nothing is blocked.

## Context
- ADR 0006 (pricing decision), `docs/prd.md` §6–7.
- Copy: `docs/design.md` §9 "Seller: billing".
- A *confirmed order* is a Manual order that entered `paid` (seller confirmed) in that calendar month, Asia/Jakarta.

## Scope
- In:
  - migration with `seller_monthly_usage` and `sellers.billing_exempt_until`;
  - `billing.RecordConfirmedOrder` called from `order.Confirm` in the same transaction;
  - meter on the seller dashboard and `GET /seller/billing`;
  - owner-only toggle to mark pilot sellers exempt.
- Out: invoices, payment of invoices, reminders (T-901). Any blocking above the quota (not wanted).

## Interfaces
```sql
CREATE TABLE seller_monthly_usage (
  seller_id                uuid NOT NULL REFERENCES sellers(id),
  month                    date NOT NULL CHECK (extract(day FROM month) = 1),  -- first day, WIB
  confirmed_manual_orders  integer NOT NULL DEFAULT 0 CHECK (confirmed_manual_orders >= 0),
  PRIMARY KEY (seller_id, month));
-- tenant RLS policy; sellers.billing_exempt_until date
```
```go
// Increments with INSERT ... ON CONFLICT DO UPDATE, month computed from `at` in Asia/Jakarta.
func RecordConfirmedOrder(ctx context.Context, tx pgx.Tx, sellerID uuid.UUID, at time.Time) error
func Usage(ctx context.Context, tx pgx.Tx, sellerID uuid.UUID, month time.Time) (Usage, error)
type Usage struct { Confirmed, FreeQuota, Billable int; Exempt bool; PricePerOrder int64 } // Rp1.000
```

## Acceptance criteria
1. The counter equals `count(*)` of Manual orders whose `paid_at` falls in that WIB month, in a test with orders around the month boundary (23:59 WIB on the last day vs 00:00 WIB on the first).
2. Confirming the same order twice (retry) counts once. Use the order state transition as the guard.
3. Above 50, orders keep working; the meter shows the billable count and Rp amount as `int64` rupiah.
4. Exempt sellers see "Masa pilot: semua fitur gratis." and `Billable` is 0.
5. Seller B cannot read seller A's usage (RLS test).

## Test expectations
- Unit: month bucketing in Asia/Jakarta with the fake clock.
- Integration: confirm path increments in the same transaction (a forced rollback leaves the counter unchanged).

## Risks and notes
- Money: `PricePerOrder` is `int64` rupiah. No floats.
- Otomatis orders are not counted here; they pay the 2% split fee.
