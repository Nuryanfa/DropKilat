# T-004 — Add seller screens to the clickable prototype

## Goal
The people we interview are sellers. In two minutes, one seller can play both sides on one phone or laptop: create a drop, watch buyers claim it live, and confirm a payment proof. The buyer side from T-001 stays as it is.

## Context
- Seller screens: `docs/design.md` §4 (S3, S4, S5, S6), §5 components, §6 copy rules, §9 "Seller: proof review".
- Flows: `docs/app-flow.md` §2 (drop lifecycle), §7 (manual payment, reject), §10 (emergency close).
- Existing prototype: `prototype/index.html`, `prototype/app.js`, `prototype/style.css`; smoke tests in `tests/prototype/`.
- PO decision 2026-11-12: show the seller side in interviews before Gate A (T-003).

## Scope
- In:
  - A view switch at the top, "Lihat sebagai: **Seller** · **Pembeli**". Both views read and write **one shared in-memory state**. A change on one side shows on the other without reload.
  - The prototype opens in the **Seller** view. `#pembeli` in the URL opens the buyer view directly, so the seller can send a buyer link in the interview.
  - **S3 Drops list:** one demo drop "Tas Sore" plus any drop made in S4, each with a status pill (Draft, Terjadwal, Live, Selesai) and quick stats (Tersedia / Lunas).
  - **S4 Drop editor (simplified):** title, one or more variants (name, price, stock), open time, hold minutes (fixed at 15, shown read-only), max per buyer, payment mode fixed to "Manual (QRIS/transfer ke rekeningmu)". The photo is a placeholder. Buttons **Simpan draft** and **Jadwalkan**. After Jadwalkan, show the drop link (`dropkilat.id/studiosore/<slug>`, labelled "Contoh") with **Salin link** and **Lihat sebagai pembeli**. Validation in Bahasa Indonesia: price > 0, stock 1–999, title required.
  - **S5 Live monitor:** big counters **Tersedia / Dikunci / Lunas / Antrean**, an event feed (newest first: "Pembeli #12 mengambil 1 tas", "Hold pembeli #4 habis, stok ke antrean #1", "Bukti transfer masuk dari pembeli #7"), and **Tutup drop** with a confirm dialog. Closing follows `docs/app-flow.md` §10: active holds keep running; the waitlist closes.
  - **S6 Proof queue:** list of submitted proofs with masked buyer phone (`0812-****-4471`), amount, time and a placeholder proof image labelled "Contoh". Buttons **Konfirmasi**, **Tolak**, **Tolak dan blokir pembeli di toko ini**, with the confirm dialog copy from `docs/design.md` §9. Konfirmasi moves the order to Lunas. Tolak releases the stock and promotes waitlist #1, as in the buyer simulation.
  - The existing "Mode demo" panel works in both views. "Simulasikan 30 pembeli rebutan" also generates 2–3 proofs from fake buyers, so S6 is never empty after a rush.
  - Seller nav on a phone: a bottom tab bar (Drop · Live · Bukti). On ≥ 1024 px: a left sidebar.
  - Update `tests/prototype/smoke.py` for the new flow.
- Out:
  - S1 login, S2 onboarding, S7 shop profile, S8 reports, CSV export, tracking numbers, label print, billing.
  - Otomatis (Xendit) payment mode, real image upload, a backend, any build tool or framework, any network request.
  - Hosting the prototype on a public URL (separate step, Nur decides where).

## Interfaces
- Files: keep `prototype/index.html` and `prototype/style.css`; split JavaScript into `prototype/app.js` (shared state, buyer view, demo panel) and `prototype/seller.js` (seller views). Plain `<script>` tags, no modules required, so it still opens as a local file.
- Shared state, all mutations through one function so both views stay in step:
  ```js
  // stock accounting must hold after every action:
  // available + held + proofSubmitted + paid === stockTotal
  dispatch({ type: "claim" | "expire" | "submitProof" | "confirm" | "reject" | "rejectBlock" | "close" | "publish", ... })
  ```
- Router: `location.hash` — `#seller/drops`, `#seller/new`, `#seller/live`, `#seller/proofs`, `#pembeli`.

## Acceptance criteria
1. Full showcase path with no reload: S4 create drop → Jadwalkan → **Lihat sebagai pembeli** → Ambil → back to Seller → S5 shows Dikunci 1 → "Simulasikan 30 pembeli rebutan" → Tersedia 0 and Antrean > 0 → S6 Konfirmasi one proof → Lunas +1 → S6 Tolak one proof → waitlist #1 gets the stock and the feed shows it.
2. After every action, `available + held + proofSubmitted + paid === stockTotal`, and no counter goes below 0. The smoke test asserts this after each step of criterion 1.
3. Tutup drop: the confirm dialog appears. After confirming, the buyer view shows the closed state, Ambil is disabled, and active holds keep their timers.
4. T-001 behaviour is unchanged: all existing smoke checks still pass.
5. Works at 360 px and 1280 px with no horizontal overflow; touch targets ≥ 44 px; contrast ≥ 4.5:1; status is never shown by color alone (`docs/design.md` §7).
6. Copy in Bahasa Indonesia; exact strings from `docs/design.md` where given; money as `Rp150.000`; times labelled `WIB`.
7. Every screen that could look real says it is an example: the drop link, QRIS, proof image and phone numbers are labelled "Contoh". No real phone numbers.
8. No console errors; no network requests after load; total size of `prototype/` < 60 KB excluding fonts.

## Test expectations
- E2E: extend `tests/prototype/smoke.py` (Playwright, headless) with criterion 1 as one scripted path, the invariant check from criterion 2 after each step, and criterion 3.
- Viewport: run the path at 360 px and 1280 px.
- Gemini QA: accessibility, copy against `docs/design.md`, and one manual run of the showcase path on a real phone. Report in `docs/tasks/T-004-qa.md`.
