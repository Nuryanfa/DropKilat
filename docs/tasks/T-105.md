# T-105 — Test plan and shared test helpers

## Goal
Every requirement and NFR has a named test before the claim engine is written, and every later test uses the same database fixture, factories and fake clock.

## Context
- `GEMINI.md` (what to attack, invariants).
- `docs/prd.md` §5–6, `docs/trd.md` §3 (NFR-1…NFR-10).
- ADR 0004 (RLS result table), ADR 0005 (stock invariant, FIFO, first fit), ADR 0003 amendment (phishing), `docs/app-flow.md` §7 (review deadlines).

## Scope
- In:
  - `docs/test-plan.md`;
  - `internal/testutil/testdb`: testcontainers PostgreSQL 17, app role as in `deploy/init-db.sql`, all migrations, a fresh schema per test or per package;
  - `internal/testutil/factory`: sellers, drops, variants, buyers, orders, waitlist entries, built through `WithSystemTx` with valid defaults;
  - `internal/testutil/invariant`: `CheckStock(t, tx, variantID)` implementing the invariant in `GEMINI.md`.
- Out: feature tests themselves (each card).

## Interfaces
```go
func testdb.New(t *testing.T) *pgxpool.Pool             // app-role pool, cleaned up with t.Cleanup
func factory.LiveDrop(t, pool, opts ...factory.Opt) (factory.Drop)
func factory.Buyer(t, pool) uuid.UUID
func invariant.CheckStock(t *testing.T, pool *pgxpool.Pool, variantID uuid.UUID)
```
The fake clock comes from `internal/platform/clock/clocktest` (T-101); do not create a second one.

## Acceptance criteria
1. `docs/test-plan.md` maps every PRD story (S-1…S-9, B-1…B-7), every business rule in PRD §6, and NFR-1…NFR-10 to a test name, its location and the card that delivers it.
2. The plan lists the ADR 0004 RLS matrix, the ADR 0005 scenarios (parallel claims, parallel expiry with newcomers, first fit, skip, stock increase) and the phishing scenario as named tests.
3. `testdb.New` starts in < 10 s on a warm Docker cache. Two packages using it in parallel do not interfere.
4. `invariant.CheckStock` fails a test with a readable diff when an order in `expired` still `holds_stock`, or when the sum does not match.
5. One example test in `internal/testutil` uses all three helpers and passes in CI.

## Test expectations
- The example test above; the helpers have their own small tests.
