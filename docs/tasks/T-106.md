# T-106 — httpx follow-ups from the T-103 review

## Goal
Fix four issues found when Claude reviewed T-103 after it merged (PR #16, merged without QA or review). They must land before the first feature handler uses `httpx`.

## Context
- `internal/platform/httpx/` as merged in `e40b8a8`.
- `docs/backend.md` §4 (problem types; `body-too-large` and `internal` added by this card's docs PR).
- `docs/trd.md` §7 (rate limits, uploads ≤ 5 MB).

## Scope
- In:
  1. **Problem mapping by type is ambiguous.** `WriteError` falls back to `errors.As` on the *type* of any registered target except `*errors.errorString`. Two sentinels of one custom type (e.g. `&DomainError{Code: "sold-out"}` and `&DomainError{Code: "drop-not-live"}`) both match every `*DomainError`, so the first registration wins for all of them. Split the API:
     - `Register(target error, typ string, status int)` matches with `errors.Is` only;
     - `RegisterType[T error](typ string, status int)` matches with `errors.As` into a `T`.
     Remove the `reflect` string check.
  2. **Rate limit runs after the body is read.** The router reads up to `BodyLimit` bytes before the limiter sees the request, so a rate-limited client still costs a full body read. Order: request id → headers → recover/log → **rate limit** → body limit → mux.
  3. **No body read deadline.** `http.Server` sets only `ReadHeaderTimeout`. With the eager body read, a client can trickle a body and hold a goroutine and buffer. Set `ReadTimeout: 30 * time.Second` (covers a 5 MB upload on a slow mobile link) and `IdleTimeout: 120 * time.Second` in `cmd/dropkilat`. Do not set `WriteTimeout` on the server: SSE (T-302) needs long writes; per-handler deadlines come with their cards.
  4. **Body read error that is not "too large"** (client disconnect, malformed chunking) returns 400 with type `validation`, but `validation` is 422 in §4. Return 400 with type `bad-request`.
  5. **Per-route body limit.** Add `func BodyLimit(n int64) func(http.Handler) http.Handler` so the upload route (P4, ≤ 5 MB) can raise the default 1 MiB limit for that route only. The router default stays 1 MiB.
- Out: proxy trust / `X-Forwarded-For` (stays ignored until deploy, P7); `/metrics` endpoint; streaming uploads instead of buffering (revisit in P4 if memory shows up in the load test).

## Interfaces
```go
func Register(target error, typ string, status int)            // errors.Is only
func RegisterType[T error](typ string, status int)              // errors.As into T
func BodyLimit(n int64) func(http.Handler) http.Handler
```

## Acceptance criteria
1. Two sentinels of the same struct type registered with different problem types each map to their own type; a third, unregistered value of that type maps to `internal` unless `RegisterType` was called for the type.
2. A request rejected by the limiter returns 429 without reading the body (test with a body reader that fails the test if read).
3. `cmd/dropkilat` server has `ReadHeaderTimeout` 5 s, `ReadTimeout` 30 s, `IdleTimeout` 120 s and no `WriteTimeout`.
4. A body read error other than `*http.MaxBytesError` returns 400 `bad-request`.
5. `BodyLimit(5<<20)` on one route accepts a 3 MiB body there while another route still returns 413 for it.
6. `go test -race ./...`, `golangci-lint run ./...` and `govulncheck ./...` pass.

## Test expectations
- Unit: the five criteria above, in `internal/platform/httpx/httpx_test.go` and `cmd/dropkilat`.
