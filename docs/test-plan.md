## 1. Test Architecture & Shared Harness

Every package and integration suite uses the shared helpers delivered in **T-101** and **T-105** so that no test invents its own database setup, time source, or stock assertion:

| Helper / Package | Signature | Purpose | Delivered by |
| --- | --- | --- | --- |
| `internal/platform/clock/clocktest` | `clocktest.NewFake(t time.Time) *Fake` | Deterministic mutex-protected clock (`Now()`, `Advance(d)`). Passed as `$now` into SQL and domain services (ADR 0005). Never call `time.Now()` in domain code or tests. | T-101 |
| `internal/testutil/testdb` | `testdb.New(t *testing.T) *pgxpool.Pool` | Starts PostgreSQL 17 via `testcontainers-go`, applies `deploy/init-db.sql` (`dropkilat_app` non-superuser role with `FORCE ROW LEVEL SECURITY` active), runs all `migrations/*.up.sql` in an isolated per-test/per-package schema or database, and returns a pool connected as `dropkilat_app` (cleaned up via `t.Cleanup`). Starts in < 10 s on warm cache. | T-105 |
| `internal/testutil/factory` | `factory.LiveDrop(t, pool, opts...)`, `factory.Buyer(t, pool)`, etc. | Builds valid sellers, drops, variants, buyers, orders, and waitlist entries inside `db.WithSystemTx` with sensible defaults and functional options. | T-105 |
| `internal/testutil/invariant` | `invariant.CheckStock(t *testing.T, pool *pgxpool.Pool, variantID uuid.UUID)` | Asserts all stock, waitlist, and state-transition invariants from `GEMINI.md` and ADR 0005 with a readable diff on failure. | T-105 (updated in T-203 for `orders.holds_stock`) |

### Universal Stock & Order Invariants (`invariant.CheckStock`)

Every stock-moving test and concurrency test calls `invariant.CheckStock(t, pool, variantID)` after commit:

```text
for each variant:
  1. available >= 0
  2. 0 <= available <= stock_total
  3. available + sum(qty of orders WHERE holds_stock) == stock_total        -- ADR 0005
  4. no order in ('expired', 'cancelled', 'rejected') has holds_stock = true
  5. no buyer has two 'waiting' entries for the same variant
  6. promotions follow FIFO order (first fit); no new claim got stock while a fitting entry was waiting
for each order:
  7. every status transition was allowed by docs/app-flow.md §5
```

> Note (T-105 → T-203): Until migration `000003_orders_holds_stock` lands in T-203, `invariant.CheckStock` computes `holds_stock` from `status IN ('held','proof_submitted','paid','shipped','completed','disputed','refund_pending','refunded')` and carries a `TODO(T-203)` marker.
